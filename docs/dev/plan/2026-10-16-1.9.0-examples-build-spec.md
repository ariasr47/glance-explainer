# Build spec: 1.9.0, a public example for every page type

Approved by Rodrigo on 2026-10-16 ("A": one example per type, an examples index page and a README thumbnail grid). It builds on 1.8.1 (`main` at `b33f303`). Read this whole file first.

## Why

The plugin has 21 kinds of page: 18 page types plus the questionnaire, the ballot and the atlas. Today only six have a public page a prospective user can open: the playbook, field guide, ballot, roadmap, the site's home page (public) and the gallery. The other examples are private, because they use real project content. This release adds one public, working example for each of the other 16.

## Ground rules (every lane)

- **Write every page fresh.** Copy nothing from private pages. Never use content from Lockercore, FormIntact, Spire OS, market-intel, Aster or any other private project.
- **Made-up topics are labelled as made up.** A page about the fictional notes app says so in its meta line: `<span>Example with made-up data</span>`. Pages about this plugin use real, public facts from this repository (git log, files, CHANGELOG) and need no label.
- **Start from the template.** Use `skills/html-explainer/assets/template.html` (1.8.1) and keep its `<style>` and `<script>` blocks exactly. Follow `SKILL.md`, `references/types.md`, `references/writing.md` and `references/design-system.md`. Every type gets its **At a glance** section as `types.md` names it (roadmap, playbook, field-guide and ballot pages are exempt).
- **The quality bar** is `skills/html-explainer/examples/playbook.html` and `field-guide.html`.
  - Real-looking content, specific numbers, plain words.
  - Four or five chapters (a playbook-length page is too long here).
  - About 8,000 to 12,000 px tall on a phone.
- **Each page passes `node skills/html-explainer/scripts/check.mjs <page>` with 0 FAIL and 0 warn.** If a warning cannot be avoided, say why in your report.
- **Check each page once in Chrome through Playwright** (`py -3` has `playwright`, channel `chrome`) at 390 and 1280 px, light and dark:
  - no sideways scroll and no console errors
  - the glance on the first screen at 1280 px
  - interactive parts work (answers, collect bar, derived pictures)
  - look at the screenshots and fix anything ugly
- Write only your own example files. Do not edit `tools/check-repo.mjs`, `.github/workflows/ci.yml`, the README or the template; the maintainer wires them up. Conventional commits (`docs(examples): ...`), no attribution trailer, no push.

## The fictional notes app (lanes 1, 2 and 4)

A small notes app built by a two-person team: Mara (product) and Ted (engineering). It has a phone app, a web app and a sync server. About 3,400 people use it each week. Version 2.3 is the current release. The team is preparing version 2.4, whose headline feature is sharing a notebook with another person. Keep names, numbers and dates consistent across pages (dates in October 2026). Invent freely within that frame, but keep it plausible and small.

## Lane 1: choosing (notes app)

Files in `skills/html-explainer/examples/`:

- `decision.html`: three rulings for 2.4. Shared notebooks: edit or view-only at launch. Conflicts: last write wins or keep both copies. A free tier limit: 3 shared notebooks or unlimited. Tap answers plus the `div.rulings` glance and one collect bar.
- `spec.html`: approve "Pin a note to the top of a notebook": before and after drawings in a `div.duo` glance, a checks board, the risks, and an approve or hold ask.
- `compare.html`: three ways to store attachments (on the sync server, in a storage service, on the device only) against five criteria. The grid is the glance, with the recommended column starred.
- `research.html`: "Why do new users stop after their first note?" from six made-up interviews and a week of made-up usage numbers. A `ul.findings` glance with strengths, sources in folds.

## Lane 2: state (notes app)

Files in `skills/html-explainer/examples/`:

- `status.html`: where 2.4 stands in week 3 of 5. A `div.duo` glance: the parts board beside a timeline with today marked, and the one blocker.
- `incident.html`: "Sync paused for 2 hours on Tuesday 13 October". An impact tiles plus timeline glance, the cause chain with the failing step, follow-ups.
- `handover.html`: Ted hands the sharing work to a new contractor. A `div.cols` glance (Verified, Only claimed, Do first), work in flight, evidence in folds.
- `portfolio.html`: a solo builder's six side projects: the notes app, a recipe site, a cycling-route map, a household budget sheet, a podcast feed and a photo-backup script. Grouped status glance (Needs you, Moving, Stalled).

## Lane 3: this plugin (real, public facts)

Files in `skills/html-explainer/examples/`:

- `release.html`: what shipped in 1.8.0 and 1.8.1, from `CHANGELOG.md` and `git log`. A `div.duo` glance (tiles beside "what you do differently").
- `pr.html`: [ariasr47/html-explainer-skill#9](https://github.com/ariasr47/html-explainer-skill/pull/9), the 1.8.1 polish. Real diff stats from `git show --stat 04cb440`, the checks, where to look first.
- `runbook.html`: cut a release of this plugin, using real commands from this repository's release flow (worktree, check-repo, version in plugin.json and the template, upgrade hash, PR, tag, GitHub release, plugin update). A `div.runbook-overview` glance. Steps with `pre.cmd`, `p.check` and `p.fail`.
- `explainer.html`: "Why every page opens with the answer", the plugin's own design idea, written for someone deciding whether to try it. The glance is the one figure that carries it.

## Lane 4: learning, using, asking, mapping

- `skills/html-explainer/examples/teach.html`: how a note travels from your phone to your other devices (notes app, for a new engineer). An `ol.layers` glance, a term box and figure in every chapter, and try-it steps.
- `skills/html-explainer/examples/tour.html`: a tour of reading a page made by this plugin, using real screenshots of `examples/playbook.html` and `examples/ballot.html`.
  - Take the screenshots yourself with Playwright, about 1000 px wide, saved as WebP, inline data URIs.
  - Steps: the answer and the three facts, the reading tools, one chapter at a time, answering a ballot card, copying the picks.
  - A `div.filmstrip` glance. Keep the file under the tour's 2,048 KB limit.
- `skills/explainer-gather/examples/questionnaire.html`: six questions for the notes app team about what the new weekly digest email should hold. Real answer fields, a `div.qprogress` glance with question 1 in it, and one collect bar.
- `skills/explainer-atlas/examples/atlas/`: an atlas of this repository, following `skills/explainer-atlas/SKILL.md`.
  - The parts: the three skills, the template, the checker, the hook, the upgrader, the site build and CI.
  - Use the real files with real line anchors, and pass `scripts/anchors.mjs` against this repository at the current commit.
  - `index.html` plus copies of `atlas.css` and `atlas.js`. The map's parts carry `data-layer`.
