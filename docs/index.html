What does a page look like?

Before this: the plugin turns what your agent did into one page you can decide from.

Every page has the same shape, so you learn it once. These are its parts, in the order you meet them.

  1. Answer barThe whole page in one sentence.
  2. Keep boxThree facts to carry, no more.
  3. Chapter mapOne line for each chapter.
  4. ChaptersA picture in each, and a remember line to close.
  5. RecapThe remember lines, collected.
  6. The askOne question, only when you must decide.

Take from this: the answer comes first, so you can stop after one sentence.

Three pages made with the plugin show the shape:

  • A plan for one risky change: moving a team wiki
  • A ballot: four decisions on one phone screen
  • Every component, with real content

Remember: Every page opens with the answer, so you can stop reading early.

What does the reader control?

Before this: sixteen page types cover the common jobs, and you ask for them in plain words.

Every page comes with the same reader tools. They sit in the side rail, or in a strip above the page on a phone.

SkimThe answer, one picture per chapter, and the remember lines.
FocusOne chapter on screen at a time.
AloudThe browser reads a chapter to you, block by block.
RulerOne block at full strength, the rest dimmed.
SizeNormal, 20 px or 22 px text.
ThemeDark or light. It follows your system until you choose.
KeysJ and K change chapter. Press ? for the list.
ResumeA link takes you back to where you left off.

Take from this: you set how the page reads, and the page never decides for you.

Each page is one file. It works offline, on a phone and on paper. Nothing moves unless you ask.

Remember: You control how the page reads, and nothing moves unless you ask.

What does it promise?

Before this: you control how the page reads, and nothing moves unless you ask.

Five promises, each backed by a file you can read. The proof sits in the fold below.

  • Checked before you see it. The agent runs a checker on every page and fixes each failure first.
  • Readable in both themes. Text keeps a contrast of at least 4.5 to 1 in light and dark, and colour is never the only signal.
  • One file, no install for the reader. Each page is a single HTML file that opens offline in any browser.
  • Answers stay with the reader. Pages that ask questions save answers in the reader's own browser until they copy them out.
  • Open and free. MIT licence, no account, no tracking.

Take from this: each promise names the file or link that proves it.

How we know
  • Checked before you see it. skills/html-explainer/scripts/check.mjs is the checker. It fails a page for a missing answer bar, a chapter with no picture, or a paragraph over forty words.
  • Readable in both themes. The same file holds the contrast rule. It works out the ratio for each text and background pair in light and in dark, and fails any pair under 4.5 to 1. It also fails a stylesheet whose done marks lose their tick, so colour is never the only signal.
  • One file, no install for the reader. skills/html-explainer/assets/template.html is the file every page starts from. Its styles and scripts sit inside it, so a page opens offline. Typefaces load from Google Fonts when you are online, and the page reads fine without them.
  • Answers stay with the reader. skills/explainer-gather/SKILL.md describes the pages that ask questions. They keep answers in the reader's browser until the reader copies or downloads them.
  • Open and free. The LICENSE file grants the MIT licence. There is no account to make and nothing is tracked.

Remember: Every promise points to the file or link that backs it.

Chapter 5 of 6, about 1 minute

How do you install it?

Before this: the plugin is free and open source, and it needs no account.

You need Claude Code. Three steps get you your first page.

  1. Add the marketplace. 
    /plugin marketplace add ariasr47/html-explainer-skill

    Check: Claude Code lists html-explainer-skill under Marketplaces.

    If it fails: check that you typed the name exactly, then run the command again.

  2. Install the plugin. 
    /plugin install html-explainer@html-explainer-skill

    Check: /plugin shows html-explainer as installed.

    If it fails: run step 1 again, then repeat this step.

  3. Restart Claude Code, then ask for a page. 
    Make an html explainer for this spec.

    Check: the agent saves the page under docs/explainers/ and gives you the link.

    If it fails: open /plugin, check that html-explainer is enabled, and restart again.

Take from this: every step ends with a check you can see, so you know it worked.

Node 18 or newer runs the checker. Nothing else to install.

Other ways to install

From a shell. Run both commands in any terminal where claude works.

claude plugin marketplace add ariasr47/html-explainer-skill
claude plugin install html-explainer@html-explainer-skill

For a whole team. Add the marketplace and the plugin to the repository's .claude/settings.json, so your team gets it too. The install guide shows the exact lines.

Other agents, such as Codex, Cursor, Gemini CLI or Copilot. Not yet tested in every agent.

npx skills add ariasr47/html-explainer-skill

The full guide is on GitHub: docs/install.md.

Remember: Two commands add the plugin. Restart Claude Code, then ask for a page.
